スケーリングアルゴリズム

ℹ️
1. Backlog per Task の計算
BacklogPerTask = SQS_VisibleMessages / MAX(RunningTaskCount, 1)
ℹ️
2. 必要タスク数の決定
DesiredTasks = CEIL(SQS_VisibleMessages / TargetBacklog)
CLAMPED = MAX(MIN(DesiredTasks, MaxTasks), MinTasks)
✅

ヘルプ: SQS Backlog AutoScaling の仕組み

📌 基本コンセプト

このダッシュボードは、SQS の滞留メッセージ数と ECS タスク数から「1タスクあたりの平均滞留量（Backlog per Task）」を算出し、AWS Application Auto Scaling により自動的にタスク数を調整する仕組みを可視化・シミュレートします。

🎯 主な機能

  • リアルタイムメトリクス: SQS滞留数、実行タスク数、Backlog/Taskをライブ表示
  • 動的スケーリング: ターゲットBacklog/Taskに基づき、最小～最大タスク数の範囲内で自動調整
  • クールダウン機構: スケールアウト 60秒（迅速）、スケールイン 300秒（安全）でフラッピング防止
  • 複数シナリオ: 通常流、スパイク、段階的負荷を1クリックで実行
  • コード生成: CDK/Terraform/CloudFormation コードを自動生成・コピー

⚙️ パラメータ調整ガイド

ターゲット Backlog/Task: 1タスクが効率的に処理できるメッセージ数。低いほど低遅延（コスト高）、高いほど高スループット（遅延大）。推奨値: 30～70件。

最小/最大タスク数: スケーリングの下限・上限。最小=0でコスト最小化、最小=1で常時稼働。

CoolDown時間: スケール直後の安定化期間。スケールアウトは短め（反応速度重視）、スケールインは長め（安全性重視）。

💡 期待される効果

  • アイドル時コスト 70% 削減（最小タスク数=0時）
  • バッチ処理 SLA 達成率向上（スパイク時も即座に対応）
  • 運用自動化 100%（人手による手動スケール不要）
